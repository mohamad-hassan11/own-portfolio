:# Creative Engineering Challenge — Portfolio Redesign

You are the lead creative director, senior frontend engineer, and technical orchestrator for this project.

## Mission

Transform my existing software engineering portfolio into a distinctive, premium-quality digital experience.

The result should feel like the work of a creative software engineer who understands design, frontend engineering, architecture, and modern web technologies.

I do not want a generic developer portfolio, a typical SaaS landing page, or a website that looks obviously AI-generated.

**You have creative freedom. Surprise me.**

## Phase 1 — Discover

Before making changes:

1. Analyze the existing Next.js project.
2. Understand its architecture, components, styling, and content management approach.
3. Identify the existing pages, projects, and design patterns.
4. Identify what makes the portfolio ordinary or visually unremarkable.
5. Develop three distinctly different creative directions.
6. Evaluate them for originality, usability, technical feasibility, and maintainability.
7. Select the strongest direction and document your reasoning.

Do not ask me to choose between the concepts. Make a justified decision independently.

## Phase 2 — Creative design

Create a coherent visual identity for the entire portfolio.

Explore ideas such as:

- Unconventional but intuitive layouts.
- Bold typography and visual hierarchy.
- Creative navigation and transitions.
- Interactive project showcases.
- Subtle animations and microinteractions.
- Dynamic visual storytelling.
- Thoughtful use of color, contrast, and whitespace.
- Technical details that reflect software engineering expertise.

These are inspirations, not mandatory requirements.

Avoid copying existing portfolio templates.

The design should have a recognizable personality.

## Phase 3 — Signature interaction

Invent and implement at least one distinctive interactive feature that makes the portfolio memorable.

It should be meaningful, not merely decorative.

Examples of the level of ambition expected:

- An interactive visualization connecting projects, technologies, and engineering skills.
- A creative project exploration interface.
- A visual engineering journey that responds to user interaction.
- A custom navigation experience that feels like exploring a digital workspace.

You are encouraged to invent something better.

Explain why your chosen interaction improves the visitor experience.

## Phase 4 — Implementation

Delegate implementation work to the appropriate developer agent.

Requirements:

- Preserve the existing Next.js architecture where reasonable.
- Preserve existing project content and MDX functionality.
- Prefer existing dependencies.
- Create reusable components.
- Ensure responsive behavior across mobile, tablet, and desktop.
- Implement keyboard accessibility and visible focus states.
- Respect reduced-motion preferences.
- Avoid unnecessary complexity.
- Maintain good loading performance.
- Use meaningful semantic HTML.

You may restructure existing UI components when justified.

## Phase 5 — Independent review

Delegate review to a separate reviewer agent.

Evaluate:

1. Visual consistency.
2. Originality.
3. Interaction quality.
4. Accessibility.
5. Responsive behavior.
6. Component architecture.
7. Performance.
8. Code maintainability.

Fix critical issues before completing the task.

## Phase 6 — Verification

Run the available linting, type-checking, testing, and production build commands.

Do not invent successful test results.

Document any checks that could not be performed.

## Phase 7 — Final delivery

Provide a report containing:

- The three creative concepts considered.
- The chosen concept and justification.
- The signature interactive feature.
- Important architectural decisions.
- Components and files changed.
- Tests performed and results.
- Known limitations.
- Suggested future improvements.

## Orchestration requirements

Use the configured specialized agents rather than performing all work in the orchestrator session.

Break implementation into manageable, verifiable milestones.

Maintain progress in persistent project files.

If context compaction occurs, preserve the implementation state and continue from documented progress.

Do not abandon the task because the first context window becomes full.

## Strict Git restrictions

Do not execute git add, commit, push, or create pull requests.

Keep every modification local.

## Success criteria

The portfolio should feel meaningfully more original, polished, and interactive than before.

The result should demonstrate independent creativity, strong engineering judgment, and successful multi-agent coordination.

Prioritize quality over execution speed.

Begin by exploring the repository and creating your creative strategy.
