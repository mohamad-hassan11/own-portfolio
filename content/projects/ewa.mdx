<JourneySection id="overview" title="Overview">

Climate Cleanup is a greenhouse management application built as part of the Enterprise Web Applications (EWA) course at the Hogeschool van Amsterdam. The Climate Control Unit (CCU-2) system combines environmental monitoring and parameter controls with historical charts, shared notes, and team management.

</JourneySection>

<JourneySection id="the-problem" title="The problem">

Greenhouse operations involve several kinds of expertise: botany, agronomy, and technology. Teams need to inspect environmental conditions, review changes over time, and share observations in the same working environment. The application brings these activities together across different greenhouses, with administrator and regular-user roles.

</JourneySection>

<JourneySection id="my-role" title="My role">

I contributed across the Angular frontend and Spring Boot backend as a full-stack member of the university project team. The features and architecture described here represent the team's application.

</JourneySection>

<JourneySection id="monitoring-and-history" title="Monitoring and history">

The application supports readings and controls for greenhouse parameters including air temperature, humidity, soil conditions, CO₂, and lighting. Its backend retrieves sensor data from MySQL and an external CCU hardware or simulator API, while the frontend presents live readings and historical trends.

Chart.js, integrated through ng2-charts, provides time-series visualisation. The history view below plots exposure and CO₂ on separate vertical axes and offers a table-view control alongside the chart.

</JourneySection>

<JourneySection id="specialist-collaboration" title="Specialist collaboration">

The notes board lets team members create, edit, and delete observations, with filters organised by specialty. This gives operational notes a place alongside the sensor views rather than leaving them separate from the greenhouse dashboard.

</JourneySection>

<JourneySection id="application-architecture" title="Application architecture">

The Angular 12 client uses TypeScript, RxJS, routing, and HTTP services to communicate with a Java 11 / Spring Boot REST API. On the backend, controllers expose endpoints for authentication, sensors, history, notes, teams, users, and settings. Services handle business operations and integrations, while Spring Data JPA repositories connect application entities to MySQL.

### Authentication and roles

Authentication uses JWTs and a custom backend request filter, with BCrypt for password encoding. Angular route guards control access to authenticated and administrator views, and an HTTP interceptor attaches the bearer token to API requests. Browser guards govern navigation; API authentication is handled separately on the backend.

The application distinguishes administrators from regular users. Administrator features include inviting users, managing team membership, and updating roles.

### External services and persistence

Spring WebClient communicates with the external CCU API for hardware or simulator readings. MySQL stores application data through JPA entities and repositories, including users, teams, sensors, sensor data, and notes. Azure storage supports avatars and file attachments, and an SMTP email service provides notifications and alerts.

</JourneySection>

<JourneySection id="account-management" title="Account management">

The settings interface brings account details, profile images, password changes, and preferences into the application. Profile-image uploads are handled through the backend file service and Azure Blob Storage.

</JourneySection>

<JourneySection id="testing-approach" title="Testing approach">

The project's frontend testing tools are Jasmine and Karma. The backend uses JUnit 5, Mockito, and Spring Boot's testing support.

</JourneySection>

<JourneySection id="result" title="Result">

The team built a full-stack greenhouse management application combining sensor monitoring and controls, historical visualisation, specialty-based notes, and account and team management. The interface captures show the history chart, collaboration board, and account settings, while the architecture connects the browser client to persistent data and external services.

</JourneySection>
