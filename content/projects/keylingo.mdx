## Overview

KeyLingo is an offline-first browser application that bridges touch-typing instruction and language learning. Traditional typing trainers treat words as arbitrary keystroke strings, offering little cognitive value to multilingual typists. KeyLingo unites physical keyboard mastery across different layouts (QWERTY US, US-International, and Arabic 101) with CEFR-graded vocabulary acquisition (A1–B2) in English, Dutch, and Modern Standard Arabic.

The application features three distinct practice modes: a 14-stage guided curriculum with progressive key unlocking, seeded reflex drills for motor agility, and a vocabulary mode with an integrated, non-penalizing word lookup drawer. The system runs entirely client-side with versioned local storage, eliminating external backend dependencies and network latency.

## Architecture and pure domain engine

KeyLingo decouples its core typing engine and Unicode text processing from the React component tree. The typing engine is structured as a pure, immutable finite state machine without DOM or framework dependencies. Every user action (`inputCharacter`, `deleteCharacter`, `pause`, `resume`, `restart`) receives the current session state and returns a new state object.

A dedicated hook (`useTypingSession`) acts as an adapter between the domain engine and React:

1. **Synchronous keystroke processing:** Keystrokes are fed directly into the state machine without asynchronous delay, ensuring zero typing latency regardless of re-render schedules.
2. **Decoupled metrics ticker:** While keystroke evaluation is synchronous, timer updates and derived speed calculations run on a 100ms interval to prevent unnecessary layout thrashing.
3. **Reactive synchronization:** Stores for user preferences, lesson progress, and personal vocabulary use `useSyncExternalStore` to ensure synchronized state across multiple components and browser tabs.

## Input pipeline and hidden textarea strategy

Capturing keyboard input in modern web applications presents significant challenges across international layouts. Relying solely on `keydown` events breaks down with dead keys (common on Dutch US-International keyboards for characters like `ë`, `é`, and `ö`) and Input Method Editors (IMEs) used for Arabic or non-Latin scripts. Furthermore, `KeyboardEvent.key` varies according to the operating system's keyboard settings rather than the physical layout being practiced.

To resolve this, KeyLingo separates physical key visualisation from character evaluation:

- **Input capture:** Keystrokes are captured via a transparent, hidden `<textarea>` element listening to native `beforeinput` and `input` events.
- **Composition guard:** The input pipeline monitors `event.isComposing`. Multi-stage dead-key and IME compositions are buffered until committed, at which point the final resolved graphemes are evaluated.
- **Anti-paste guard:** Native and synthetic paste actions are intercepted and prevented, preserving authentic typing measurement.
- **Physical layout illumination:** The `keydown` event is used exclusively to read `event.code` (the physical key position), driving visual press states on the virtual keyboard without affecting text verification.

## Multilingual Unicode and Arabic diacritic engine

Handling Arabic and multi-byte Latin diacritics in JavaScript requires careful text segmentation:

- **Canonical NFC normalization:** All source texts and user inputs are normalized using `String.prototype.normalize('NFC')`. This resolves platform-level divergence where macOS emits decomposed Unicode (NFD) while Windows emits precomposed characters (NFC).
- **Grapheme segmentation:** Standard string indexing and regular expressions split surrogate pairs and combining characters improperly. KeyLingo uses the native `Intl.Segmenter` API configured for grapheme clusters, treating base letters and stacked diacritics as single visual and logical typing units.
- **Configurable Arabic diacritic matching:** In everyday Arabic typing, diacritics (_tashkeel_) are often omitted, whereas language learners require them. KeyLingo implements two comparison modes: **strict** (full diacritic verification) and **lenient** (stripping short-vowel marks via `/[\u064B-\u0652\u0670]/g` prior to evaluation).
- **Bidirectional layout handling:** The practice interface dynamically switches directionality (`dir="rtl"`) when Arabic content is selected, while the virtual keyboard remains pinned to `dir="ltr"` to preserve physical hardware geometry.

## Practice modes and curriculum design

The application organizes practice into three complementary workflows:

### 1. Guided curriculum

The guided curriculum consists of 14 progressive lessons per keyboard layout (QWERTY US and Arabic 101). Lessons introduce keys incrementally: starting with home-row tactile anchors (`F` and `J`), progressing through index/middle reaches, top and bottom rows, numerals, and shift-key modifiers.

A lesson gating engine evaluates performance upon completion: subsequent lessons unlock only when the user satisfies both minimum Net WPM (e.g., 15 WPM) and minimum accuracy (e.g., 90%) thresholds.

### 2. Seeded reflex training

Reflex training develops motor reflexes for difficult character sequences, adjacent keys, and alternating-hand transitions. To make exercises reproducible and shareable, KeyLingo incorporates a pure 32-bit Mulberry32 pseudo-random number generator (PRNG). Given the same numerical seed, the generator deterministically reproduces identical character streams across devices.

An optional **adaptive mode** inspects the user's historical error log, dynamically increasing the probability of character sequences that target frequently missed keys.

### 3. Vocabulary practice and word lookup

The vocabulary engine pairs typing drills with curated bilingual word collections across English, Dutch, and Arabic. Content is indexed across four CEFR proficiency levels (A1 through B2) and topic categories including Everyday Life, Formal & Polite, Workplace, and Technology.

During practice, clicking any word token or pressing a dedicated shortcut opens a slide-in translation drawer. The drawer presents the translation, grammatical part of speech, contextual usage notes, and example sentences. Crucially, opening the panel automatically pauses the typing timer and does not count as a typing mistake. Users can bookmark words into a personal vocabulary deck for subsequent review.

## Adaptive theming and visual ergonomics

To accommodate diverse ambient lighting conditions and prevent eye fatigue during extended practice, KeyLingo provides full first-class support for both dark and light modes. Theming is managed via Tailwind CSS class switching on the document root, automatically synchronizing with system color preferences on initial launch and persisting manual overrides in local storage.

Visual hierarchy, character contrast ratios, and interactive states are specifically tuned for each mode. In dark mode, subdued background surfaces eliminate glare for nighttime typing. In light mode, high-contrast character typography, distinct key boundaries, and active cursor indicators ensure sharp daytime readability.

## Typing metrics and persistence

KeyLingo implements standardized typing calculations verified against documented test vectors:

- **Gross WPM:** `((totalCharacters / 5) / elapsedMinutes)`
- **Net WPM:** `Math.max(0, grossWpm - (uncorrectedErrors / elapsedMinutes))`
- **Accuracy:** `(correctCharacters / totalKeystrokes) * 100`

Pause durations are deducted from elapsed time so that looking up a word's translation does not distort speed metrics.

All user data (preferences, lesson unlock progress, error history, and vocabulary items) is managed through a versioned `localStorage` persistence service. Each stored key wraps payload data in a versioned envelope (`{ _version: number, data: T }`). When schema updates occur, migration functions execute sequentially to guarantee backwards compatibility. The service also provides full JSON export and import capabilities.

## Testing and quality assurance

The codebase incorporates a comprehensive test suite executed across unit, integration, and browser levels:

- **Vitest suite:** 400 tests across 23 test files covering state machine transitions, grapheme segmentation, PRNG determinism, lesson gating rules, and storage migration stress tests. The core typing engine achieved **100% branch test coverage**.
- **Playwright end-to-end tests:** Browser automation scripts validating end-to-end typing sessions, dead-key buffering, IME composition sequences, modal timer pausing, and responsive drawer behavior.
- **Strict TypeScript:** Zero usage of `any`, strictly typed immutable domain models, and complete separation between presentation and business logic.

## Result

KeyLingo provides a responsive, offline-first typing trainer that demonstrates modern full-stack web engineering. By decoupling domain logic into a pure TypeScript state machine, employing native Unicode segmentation, and implementing a resilient hidden-input strategy, the application delivers a seamless typing experience across diverse languages and keyboard layouts.

## What I learned

- **Unicode is non-trivial:** Standard JavaScript string indexing (`length`, `charAt`, `split('')`) is insufficient for internationalized text. Building for Arabic and European diacritics demonstrated the necessity of grapheme-level segmentation and canonical normalization.
- **State machine architecture pays off:** Keeping the typing engine 100% pure and independent of React simplified unit testing and ensured zero typing latency. Adapting the engine to React via `useSyncExternalStore` provided clean reactivity without component coupling.
- **Input accessibility requires careful trade-offs:** Capturing raw keystrokes while maintaining support for IMEs, dead keys, and mobile virtual keyboards requires balancing native browser input events with synthetic visual models.
