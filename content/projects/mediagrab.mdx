## Overview

MediaGrab is a media downloading application I built as both a **Windows desktop application** and a **web application**.

The application allows users to provide a supported media URL, choose between audio or video, select the desired quality, and download the processed media. Under the hood, MediaGrab uses **yt-dlp** for media extraction and **FFmpeg** for audio conversion, video processing, and merging separate video and audio streams.

The project eventually grew beyond the application itself. I containerized the web backend with Docker, created a Docker Compose deployment, configured a computer as a local server, and exposed the application securely to the internet through a **Cloudflare Tunnel** and my own domain.

## Motivation

The project started with a simple goal: build an easy-to-use tool for downloading audio from supported media sources without depending on third-party downloader websites.

Rather than creating only a wrapper around an existing command-line tool, I wanted to build the complete experience myself and explore the different ways the same functionality could be delivered.

This resulted in two implementations:

- A native Windows desktop application
- A browser-based application backed by a media-processing API

The project also became an opportunity to work with media processing, asynchronous backend jobs, Docker, networking, self-hosting, and deployment.

## Desktop Application

The first version of MediaGrab was developed as a native Windows application using **C# and WPF**.

The desktop application provides a simple interface where the user can enter a media URL, select whether the result should be audio or video, choose the desired quality, and select where the downloaded file should be saved.

The application starts and manages yt-dlp as a background process and uses FFmpeg for post-processing.

Main functionality includes:

- Downloading audio as MP3
- Downloading video as MP4
- Selecting audio and video quality
- Combining separate video and audio streams
- Converting extracted audio using FFmpeg
- Displaying download progress, speed, ETA, and processing state
- Selecting a destination folder
- Handling invalid URLs and download failures
- Publishing the application as a self-contained Windows application

The desktop version was also useful for understanding how yt-dlp and FFmpeg behave before moving the media-processing logic to a server environment.

## Web Application

After completing the desktop version, I implemented a web version using **Next.js, TypeScript, React, and Tailwind CSS**.

The web interface provides the same core workflow as the desktop application:

1. Enter a supported media URL
2. Select audio or video
3. Select the desired quality
4. Start the download
5. Follow the progress in the browser
6. Receive the processed file when the job is complete

The frontend itself does not perform media processing. Instead, it communicates with a separate FastAPI backend responsible for the actual download and conversion process.

This separation keeps the user interface lightweight while allowing the media-processing environment to run independently.

## Backend Architecture

The backend is written in **Python using FastAPI**.

Instead of making the browser wait for a single long-running HTTP request, MediaGrab uses a job-based workflow.

A download request creates a job on the server and immediately returns a job identifier. The frontend then polls the backend for the current state of that job.
