Play against a random computer throw and review history and statistics.

**Implementation highlight.** Enums model throws and outcomes; a winner function determines results, Room converters persist them, and aggregate DAO queries expose win, loss, and draw counts.

### Architecture & evidence

This independent Kotlin application uses Jetpack Compose and Material 3. Its Gradle settings include a single `:app` module. Relevant implementation files: `Utils.kt`, `GameDao.kt`, `Converters.kt`, `AppPlayGameScreen.kt`, `AppHistoryScreen.kt`.

### Runtime verification

Played three rounds and opened history to verify that recorded throws and outcomes were visible. History ordering remains subject to the query limitation noted below. The captured app was rebuilt from a source-fingerprint-checked disposable copy using a separate .portfolio package ID. The existing template JUnit test passed. Nine supplementary checks passed for every user/computer throw combination. Supplementary tests were added only to the disposable copy. Android instrumentation tests were not run. Build and capture provenance are recorded in the import manifest.

### Constraints & follow-up

The history query uses ORDER BY gameDate = 'des', which does not establish descending date order. Game insertion is initiated during composition, a lifecycle concern.
